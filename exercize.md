# Exercise: HTTP Requests Basics (Go)

## Задание 1 — Счетчик запросов

Сделай HTTP-сервер с двумя endpoint:

- `GET /`
  - увеличивает счетчик запросов на 1
  - возвращает текст: `welcome, request #N`

- `GET /count`
  - не увеличивает счетчик
  - возвращает текущее значение счетчика: `count: N`

## Требования

- Используй `atomic.Uint64` для счетчика.
- В endpoint `/` логируй номер запроса в консоль.
- Решение должно корректно работать при параллельных запросах.

## Подсказка

- Объяви в `main`:
  - `var reqCount atomic.Uint64`
- В обработчике `/`:
  - `n := reqCount.Add(1)`
- В обработчике `/count`:
  - `n := reqCount.Load()`

## Проверка

1. Запусти сервер.
2. Открой `GET /` три раза.
3. Открой `GET /count`.
4. Ожидаемый результат: `count: 3`.

## Дополнительно (по желанию)

- Добавь endpoint `POST /reset`, который сбрасывает счетчик в 0.
- Возвращай JSON вместо plain text.

## Задание 2 — Heartbeat cron

Добавь `gocron`-задачу, которая выполняется каждую секунду и пишет в лог:
`heartbeat <текущее время>`.

### Требования

- Используй `gocron.Every(1).Second().Do(...)`.
- Scheduler должен быть запущен (`gocron.Start()`).
- HTTP-сервер продолжает отвечать на `GET /` во время работы cron.

### Проверка

1. Запусти сервер.
2. Убедись, что в логах каждую секунду появляется `heartbeat ...`.
3. Параллельно отправь несколько `GET /` и проверь, что ответы приходят.

## Задание 3 — Метрики cron через API

Добавь атомарный счетчик запусков cron и время последнего запуска.
Сделай endpoint `GET /stats`, который возвращает:
`http_requests`, `cron_runs`, `last_cron_run`.

### Требования

- Счетчики/состояние потокобезопасны (`atomic` или `mutex`).
- Данные корректны при параллельных запросах к `/` и фоне cron.

### Проверка

1. После запуска подожди 3-5 секунд.
2. Открой `GET /stats`.
3. Убедись, что `cron_runs > 0`, а `last_cron_run` обновляется.

## Задание 4 — Управление cron (start/stop/status)

Сделай endpoint:
- `POST /cron/start`
- `POST /cron/stop`
- `GET /cron/status`

### Требования

- Повторный `start` не должен создавать второй активный scheduler.
- `stop` должен быть безопасным, даже если cron уже остановлен.
- `status` должен возвращать состояние (`running/stopped`) и количество запусков.

### Проверка

1. Вызови `POST /cron/start`, проверь рост `cron_runs`.
2. Вызови `POST /cron/stop`, проверь, что рост остановился.
3. Снова `POST /cron/start` и проверь, что рост возобновился.
